APPROACH 2 • RECOMMENDED NOW

SLA-Driven Controlled Parallelism — Airflow + Spark on Kubernetes

Modernize orchestration and execution without introducing a new queueing platform yet. Airflow remains the workflow brain; concurrency is explicitly governed and Kubernetes provides elastic compute.

Advantages

  • Low-to-medium migration complexity; fits Airflow naturally.
  • Controls peak infrastructure and downstream pressure.
  • Concurrency is configuration, not hard-coded application logic.
  • Dedicated batch nodes + autoscaling improve isolation and cost efficiency.
  • Creates a clean stepping stone to Approach 3.

Trade-offs

  • Concurrency is still mostly static/configuration-driven.
  • Airflow pools are not a full enterprise fairness/policy engine.
  • Very large multi-domain bursts can eventually require stronger admission control.

Why Choose It Now

  • Matches the current Ab Initio → PySpark modernization scope.
  • Avoids over-engineering while establishing workload governance.
  • Lets the team prove Spark sizing and concurrency using production history.
  • Provides immediate cost/SLA benefits without adding queue infrastructure.
